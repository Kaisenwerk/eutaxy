# @eutaxy/cli

**Purpose.** The `eutaxy` command: `check`, `report`, and later `prover install`, config loading, engine discovery.

**Public surface.** `main` (the command), `runCheck`, `cloudflareRegressionTest`, the generators for the check test and Vitest config, and `checkInWorkerd` with its `CheckTransport` (the half of the check that runs inside workerd: the generated test holds only its module globs and one call to it; `workerd.ts` and `keys.ts` import nothing that needs Node). `eutaxy check <scenario.sim.ts>` writes `<dir>/.eutaxy/`, runs the user's Vitest with the Cloudflare plugin there, reads the verdict back from the test's task meta through Vitest's JSON reporter, prints text or `--json` (`--exhaustive` runs every schedule within the bounds), writes `<name>.regression.test.ts` on a violation, and exits 0/1/2 for BOUNDED/VIOLATED/UNSUPPORTED (1 also when a spec is REFUTED). For a scenario's `specs`, it reads every spec file next to the scenario with its module into `SpecIR` on the Node side (`findSpecModules`, through `@eutaxy/prover/reader`) and writes `.eutaxy/specs.ts`, which maps each module to its specs as plain data and a lazy loader of its spec file (`specFiles`); the generated test observes the listed modules while the scenario runs, loads their spec files, and reports their spec verdicts; a listed module that is missing or whose spec file does not read exits 3. `--prover <name>` (`lean`, `smt`, or both separated by a comma) runs the `PROVEN` rung on the Node side after the check: each named engine on each observed module's source (`proveSpecs`, the engines in `provers`), folded into the spec verdicts by `aggregate`; a `CONFLICT` exits 1 like a refutation, an unknown engine name 3 (`enginesNamed`). `eutaxy report [dir]` (`runReport`) runs every spec file under the directory (default the working directory) on the Node side, with no scenario: each module and its spec file are imported in a worker thread of their own, started on `report.ts` itself, where a relative import from a `.ts` file resolves as TypeScript resolves it (`./domain.js` and `./domain` find `domain.ts`) (`testModule`: the module's output goes to stderr, its state starts fresh, and a module that does not load, or whose properties do not finish within `moduleBudgetMs`, default 60 s, leaves its properties `UNKNOWN`), the ladder starts at `TESTED` (`checked: false`) with `--seed` (default `report`), `--prover` adds the `PROVEN` rung as `check` does, and the verdicts print by module with a count, or `--json`; it exits 1 for a `REFUTED` or `CONFLICT` spec (an `UNKNOWN` fails nothing), 3 for a spec file that does not read, no spec files, an unknown engine, or a flag only `check` takes. On either command a value flag given without a value is an error.

**May import.** `@eutaxy/spec`, `@eutaxy/core`, `@eutaxy/engine`, `@eutaxy/cloudflare`, `@eutaxy/prover`, `@eutaxy/prover-lean`, `@eutaxy/prover-smt`, `@eutaxy/report`, `@eutaxy/aws`. Only these are declared in `package.json`, and
pnpm links only declared workspace dependencies, so an import of any other
package does not resolve. The project references in `tsconfig.json` mirror the
list; a test keeps the two in sync with the design.

**Phase.** v0.4 onward. See `docs/design.md` and `docs/roadmap.md`.
