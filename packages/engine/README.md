# @eutaxy/engine

**Purpose.** The platform-neutral run loop: virtual clock, globals patching, per-run state reset, replay, and the turns of concurrent invocations.

**Public surface.** `explore` (seeded or, with `exhaustive`, every schedule within the bounds with partial-order reduction; replay, shrink, verdict), `Chooser` and `ChoiceOption` (how a run makes its choices, faults and turns alike: `seededChooser` draws them from the seed, `replayChooser` looks them up in a schedule, the exhaustive enumerator picks them, and `limitFaults` applies the fault bound to one; `exhaustive-model.test.ts` holds the enumerator to core's proved model `schedules` on every tree of choices up to a bound), `replay` and `replayRun` (re-run a schedule exactly), `shrink` and `restrictSpec`, `runOnce`, `Run` (the per-run hooks proxies call), `runInvocation` and `Outcome` (the delivery skeleton every platform shares: user code run as an invocation under settle, ended as completed, errored or crashed), `note` (a platform action that performs nothing, recorded as a marker effect) and `decide` (a decision of the platform's own under decision faults, which stands or crashed the invocation), `hostInvocation` (user code run as an invocation of its own inside the effect being performed, for a called Worker's code inside the call: its effects are its own and turns of their own, a fault inside it ends it alone, and the hosting invocation's own code stays its own meanwhile), `CrashSignal`, `InjectedEffectError`. `proxiedSide`, `rawRun` (with `RawSide`, `RawContext`, `RawAttempt`, `RawOutcome`), `compareSides` and `DifferentialStuck` (the platform-neutral part of a differential check: the fault-free proxied run, the raw side's loop under the same virtual globals and scripted externals with the same pick of the next event and the same redelivery rule, and the comparison; a platform writes only how one raw attempt calls its handler and what its record holds). `observeCore` (wraps a module namespace's functions so calls made while a run is installed are recorded, with their arguments, and logged as decisions of the invocation running; `Run.decision` is where they land, summarized by core's `toJson`). `patchProperty` (the one way a property is replaced for a while and put back exactly; the globals patch, scripted `fetch`, `observeCore` and the AWS SDK proxy use it). `patchGlobals`, `VirtualClock`, `VirtualRandom`, `settleOn` (the virtual clock and the globals patch; `Run.install`/`uninstall` apply them per run and `Run.settle` waits under them).

**For a platform's delivery.** In a concurrent run the scheduler sees an invocation at work only inside an effect frame (`hooks.effect`, `effectSync`) or parked at one, and sees a wait only when it is a run of a live invocation (`runInvocation`); so every real wait a delivery makes (a call into the runtime, a gate on another event, a turn of the event loop) goes inside an effect of the invocation that waits, a wait on a crashed invocation returns at once and leaves its work unseen, and a bare await outside any frame ends the run with "made no progress and cannot be abandoned" or "waiting on something Eutaxy cannot see". Code an object runs on its own after a plain await is attributed to the last invocation run as, so an effect that must be attributed right starts in a fresh `runInvocation`. Code of another invocation that an effect runs (a called Worker's) goes through `hostInvocation`, never a bare `runInvocation` inside the perform: inside a perform timers are the library's and real, a sequential run would attribute the host's own code to the hosted invocation once it ran, and the hosting effect would count as I/O while the hosted code waits. `finish` runs after `uninstall`: the real globals are back, nothing a handler does there is recorded, and application code the platform wakes there (a close handler, a constructor) runs outside the simulation; keep it to reading state and tearing down, under `withoutNetwork`.

**May import.** `@eutaxy/core`, and from the host only what it patches:
`node:async_hooks` (through `process.getBuiltinModule`, so a host without it
still loads) to keep an SDK's timers real during an effect's I/O while the
handler's stay virtual. Only these are declared in `package.json`, and
pnpm links only declared workspace dependencies, so an import of any other
package does not resolve. The project references in `tsconfig.json` mirror the
list; a test keeps the two in sync with the design.

**Phase.** v0.4 onward. See `docs/design.md` and `docs/roadmap.md`.
